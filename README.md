# HHCLUB 自动抽奖 · 庆典版

HHCLUB 四周年庆典抽奖的油猴脚本，在 `lucky.php` 页面挂一个悬浮 Dashboard，自动抽奖并统计战绩。

本版本的重点是**把每个奖项中了多少次真正显示出来**，同时修掉了原版的几个会影响实际抽奖行为的问题。

- 适用站点：`https://hhanclub.net/lucky.php`
- 授权协议：MIT

## 功能

### 🎁 奖项明细（本版本重做）

按奖项类别聚合，每个类别显示**中奖次数 + 占比 + 占比条 + 累计数值**，点击可展开该类别下的具体档位：

```
🎁 奖项明细                          共 128 抽 · 6 种
──────────────────────────────────────────────
💰 憨豆        62 次  48.4%  ████████████
   累计 41,500
   ├ 500 憨豆      41 次
   ├ 1,000 憨豆    19 次
   └ 5,000 憨豆     2 次
🔮 魔力值      28 次  21.9%  █████
🌈 彩虹ID      15 次  11.7%  ███
⭐ VIP         12 次   9.4%  ██
🎫 补签卡       8 次   6.3%  █
📧 邀请         3 次   2.3%  ▌
```

识别的奖项类别：憨豆、魔力值、邀请、彩虹ID、VIP、补签卡、上传量，认不出来的统一归到「其他奖品」并原样保留文案。

### 📊 汇总统计

抽奖次数、奖项种类数、累计消耗、获得憨豆、憨豆盈亏 / 盈亏率，以及邀请、彩虹ID、VIP、补签卡、上传量、魔力值六项累计。支持「本次数据 / 历史总计」切换，历史数据存在 `localStorage`，关页面不丢。

### 📤 CSV 导出

一键导出当前视图的分奖项明细（含类别小计和各档位），带 BOM，Excel 打开中文不乱码。方便自己拉表算真实爆率。

### ⚙️ 其他

- 抽奖间隔、最大次数、视图模式、面板位置、动画开关全部持久化
- 中奖动画可关闭（高频抽奖时能省不少性能）
- 面板可拖动、可缩放，支持触屏
- 多标签页同时开着不会互相覆盖统计数据

## 相比原版（v1.0.3）改了什么

### 奖项统计

| # | 说明 |
|---|---|
| 1 | **详细奖品统计根本显示不出来。** 容器 `#prize-stats` 写死了 `display:none`，而代码里没有任何一处把它改回来 —— 那个「展开详细奖品统计」按钮从来没出现过，统计数据一直在往不可见的 DOM 里写。这是「不知道每个奖项中奖次数」的直接原因。 |
| 2 | **统计粒度按原始文案分组，会碎成一堆条目。** 原本 key 是完整奖品文案，"恭喜获得 500 憨豆" 和 "恭喜获得 1000 憨豆" 算两个独立奖项，抽多了列表几十条，看不出「憨豆一共中了几次」。现在改成「类别 → 档位」两层聚合。 |
| 3 | **魔力值被当成憨豆。** 原本 `魔力` 和 `憨豆` 都归到 beans 且计入盈亏，导致盈亏算错。现在拆成两个类别，盈亏只算憨豆。 |
| 4 | 抽奖次数、消耗、分奖项统计改为一次性写入，不再有 `updatePrizeStats` / `updateCostStats` 分两步造成的中间态。 |

> 转盘是 100% 有奖的，所以原版「本次中奖」这个数字恒等于抽奖次数、没有信息量，改成了**奖项种类数**。

### 行为问题

| # | 说明 |
|---|---|
| 5 | **并发抽奖。** 原本用 `setInterval` 周期调用 `async` 的抽奖函数，请求一旦慢过间隔就会同时飞出多个请求，既重复扣豆也会触发站点的重复点击风控。改成 await 完成后再排下一次的串行循环。 |
| 6 | **定时器泄漏。** `startLottery()` 里先不 await 地调一次抽奖，紧接着把 `setInterval` 赋给 `lotteryTimer`；如果那次调用内部触发了 `restartLotteryTimer()`，它建的 timer 引用会被覆盖，再也 clear 不掉，停止后仍在后台抽。改成串行循环后不复存在。 |
| 7 | **退避后间隔降不回来。** `setInterval` 的周期在创建时就固定了，改 `dynamicInterval` 变量对它无效 —— 被限流撑到 30 秒后，即使之后一直成功也永远回不到 7 秒。 |
| 8 | **单次消耗解析错误。** `match(/(\d+)/)` 遇到 "2,000" 只会取到 `2`，于是 `singleCost = 2`，可抽次数变成天文数字、成本和盈亏率全错。旁边的余额解析做了去逗号处理，这里漏了。 |
| 9 | **接口连续报错不会停。** 非限流类错误只是累加计数器然后什么都不做，接口要是一直 500 会无限刷请求。现在连续 5 次失败 / 连续 12 次被限流自动停止。 |
| 10 | 请求间隔加入 ±15% 随机抖动，不再是固定频率。 |
| 11 | 停止按钮可立刻中断等待，不用等满当前间隔。 |

### 其他

- 设置项和面板位置持久化；运行中修改间隔立刻生效，不必重启
- 拖动兼容触屏（原本只绑了 mouse 事件，手机上拖不动）
- 多标签页统计改为读-改-写，不再互相覆盖
- 日志上限 20 → 50 条
- 代码整体重排，`current` / `total` 两套统计改为同构结构，渲染逻辑合并成一份

### 数据迁移

存储 key 从 `hhanclub_lottery_stats_v3` 升到 `v4`，首次运行会自动迁移：原有累计值直接搬过来，`totalPrizeStats`（原始文案 → 次数）逐条重建成新的分类结构。**历史数据一条不丢**，旧 key 也保留着不删。

## GreasyFork 同步

脚本头里**不要**写 `@downloadURL` / `@updateURL` —— 那两行是 GreasyFork 发布时自动注入的，源文件里留着会重复。

在 GreasyFork 脚本管理页选择「从代码仓库同步」，同步地址填：

```
https://raw.githubusercontent.com/SAGIRIxr/HH-Automatic-lottery/main/hhclub-auto-lottery.user.js
```

之后每次改动只要提交到默认分支并升高 `@version`，GreasyFork 就会自动拉取新版本。
